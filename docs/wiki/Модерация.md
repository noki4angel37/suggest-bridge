# Модерация

Заявка попадает в очередь **один раз**. Решение можно принять в Telegram или Discord: события ядра (`SubmissionSubmitted`, `Approved`, `Scheduled`, `Rejected`, `Published`) обновляют карточки на обеих платформах и уведомляют автора.

## Карточка (мок)

```
┌─────────────────────────────────────────────┐
│  ⏳ Заявка #42 · Discord                    │
│                                             │
│  Предложить добавить FAQ по установке       │
│  Docker для новичков.                       │
│                                             │
│  👤 Аноним                                  │
│  🗨 Discord                                  │
│                                             │
│  [ ✅ Одобрить ] [ ❌ Отклонить ]           │
│  [ ✉️ Ответить ] [ 🕒 Отложить ]            │
└─────────────────────────────────────────────┘
```

## Действия

| Действие | Поведение |
|----------|-----------|
| Одобрить | Публикация по `publish_target` (TG / DS / both) |
| Отклонить | Причина (FSM в TG, TTL 15 мин) → автору |
| Ответить | Сообщение автору без публикации |
| Отложить | Планировщик публикует в указанное время (время сервера процесса; отмена — через повторное решение/очередь) |
| Цель публикации | TG, Discord или оба |

`/queue` (TG и Discord) показывает pending и **отложенные** публикации. Повторный approve/reject **идемпотентен** (CAS): «Заявка уже обработана».

Если approve прошёл, а пост в Discord не появился — снова «Одобрить» (retry). Смотрите логи. Runbook: [[Устранение-неисправностей]].

## Dual-publish и rollback

1. Публикация в выбранные цели через `PublishRouter`.
2. При ошибке второй стороны — удаление уже опубликованного (включая **все** id альбома в Telegram).
3. Mirror stubs очищаются, чтобы не оставить «дыры» в зеркале.

## Анонимность

- Автор может скрыть имя в **публикации** (подпись `Аноним` / `ANON_NAME`).
- **Модераторы** на карточке всегда видят автора.
- В Discord канал заявок: исходное сообщение удаляется после ingest (нужен Manage Messages).

## Зеркало ленты

- По умолчанию включено (`mirror_enabled` в settings БД).
- Пост в TG-канале → копия в Discord `#предложка` и наоборот.
- Публикации из модерации **не** дублируются зеркалом (stub до Discord-стороны).
- Длинный текст обрезается: Discord **2000**, TG caption **1024**.
- Управление: `/mirror on|off` в Telegram — [[Команды]].

## Антифлуд

- Глобальный лимит заявок на пользователя (TG: `/antiflood`, DS: `/antiflood_config`).
- Per-guild лимит Discord: `/ratelimit_config`.
- Счётчики в SQLite с `BEGIN IMMEDIATE`.
- При превышении автор получает отказ на submit (заявка не в очереди). Стартовые значения смотрите командами без аргументов; типично начинают с небольшого `limit` и окна в минуты — подстройте под активность сообщества.
- Для ручного выравнивания TG→DS после сбоя зеркала: `/repost <tg_message_id>` (админ TG).

## Медиа

Вложения Discord читаются через API бота **до** удаления сообщения из канала заявок и кэшируются (локальный media store). Карточка показывает превью из кэша, не с CDN. Telegram `file_id` скачивается в момент публикации в Discord при необходимости.

Опубликованный пост (мок):

```
Предложить добавить FAQ по установке Docker для новичков.

👤 Аноним
🗨 Discord

#предложка
```
