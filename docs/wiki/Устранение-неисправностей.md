# Устранение неисправностей

Сначала таблица (триаж), ниже — runbook’и для P0/P1 сценариев.

## Триаж

| Симптом | Проверка |
|---------|----------|
| Бот не стартует | `.env` / `/etc/suggest-bridge/env` заполнен; venv; traceback |
| `HOST_SYNC_SECRET is required` | Задайте секрет **или** не используйте агент |
| `host-sync: bad signature` | Разный секрет на ПК — runbook ниже |
| Duplicate Discord posts | Один процесс; mirror stub на `main` |
| Approve OK, поста нет | Retry «Одобрить»; PublishRouter; права |
| Health 503 / `degraded` | Разберите `checks.*` — runbook; модули: [[FAQ-модулей]] / [[Module-FAQ-en]] |
| `checks.modules` = false | [[FAQ-модулей]] · [[Module-FAQ-en]] · `python -m bot.core.module_loader` |
| `database is locked` | Один primary — runbook |
| Зеркало молчит / дубли | `/mirror`; один поллер — runbook |
| `/host` не видит ПК | Агент; Syncthing; registry; секрет |
| FSM «Сессия истекла» / черновик пропал | Ожидаемо (15 мин / MemoryStorage) |
| Slash-команд нет | [[Слэш-команды-Discord]]: лог `Guild … slash`; scopes `applications.commands`; перезапуск клиента Discord; процесс бота жив |
| Сообщения в канале заявок не удаляются | Invite **268561488** (Manage Messages) |
| `/setup_suggest` Forbidden на роли | Нужен Manage Roles в invite (**268561488**) |
| `aiohttp unavailable; HEALTH_PORT ignored` | `requirements.txt` |
| Standby timeout | `HOST_STANDBY_WAIT_SEC`; primary не дал `go_primary` |
| Lease требует consent | `HOST_REQUIRE_CONSENT=1` → `/host_consent` |
| Бот молчит | Runbook ниже |
| Два primary | Runbook ниже |

## Runbook: бот молчит

1. Процесс жив? (`docker ps` / `systemctl status` / Task Manager).
2. `curl -s http://127.0.0.1:${HEALTH_PORT:-8080}/healthz` — разберите `checks`.
3. Режим `.env` соответствует платформе (TG / DS / both). `REPLACE_ME` ≡ unset.
4. **TG:** в логах `Conflict` / `getUpdates`? Второй инстанс с тем же `BOT_TOKEN`? `/host_status` — кто primary?
5. **DS:** intents; бот на guild; `/setup_suggest` выполнен.
6. Логи: `docker compose logs --tail=200` / `journalctl -u suggest-bridge -n 200`.
7. Тест: `/start` или заявка. Не запускайте второй поллер «для проверки».

## Runbook: два primary / конфликт lease

1. На каждом ПК: `/host_status` — holder, TTL, heartbeat.
2. Остановите лишний `python -m bot.main` / агент. Оставьте одного кандидата.
3. На лишнем: `/host_release`. На нужном: `/host` → claim (`/host_consent` если включён consent).
4. Логи: один long polling; нет `terminated by other getUpdates`.
5. Health → желательно `"status":"ok"`.
6. Syncthing отстаёт — дождитесь sync `state.json`/`acks/`, не форсите claim с двух сторон.
7. Split-brain: остановите все агенты → один `bot.main` → снова агенты.

## Runbook: database is locked

1. Найдите процессы: Linux `pgrep -af 'bot.main'`; Windows — Task Manager / процессы python с CommandLine.
2. Оставьте один; остальные — graceful stop (`systemctl stop` / Ctrl+C), не сразу kill -9.
3. `BRIDGE_DB_PATH` не на «плохом» сетевом диске с locking.
4. Перезапустите один primary. `-wal`/`-shm` не удаляйте при живом процессе.
5. Не «чините» копированием БД во время записи. После — `/queue` + тестовая заявка.

## Runbook: Approve OK, поста нет

1. Снова «Одобрить» (retry approved-but-unpublished).
2. `/queue` — статус `approved` vs `published`.
3. `publish_target` на карточке: проверьте **нужный** канал.
4. Права: TG — Post Messages; Discord — Send/Embed/Attach в целевом канале.
5. Логи `PublishRouter`: rollback мог удалить уже сделанный пост (альбом TG целиком).
6. Исправьте права/канал → снова Approve; не дублируйте пост вручную.

## Runbook: зеркало молчит

1. `/mirror` — enabled? Иначе `/mirror on`.
2. Источник — обычный пост канала, не модерационная публикация.
3. Лимиты длины: DS 2000, TG caption 1024.
4. Права бота в обоих каналах ленты.
5. Один primary.

## Runbook: дубли в Discord

1. Один `bot.main` (второй поллер → дубли).
2. На актуальном `main` stubs глушат модерационный повтор; обновите код и рестарт.
3. Не чистите БД ради stubs без бэкапа. Тест: один пост в TG-канале.

## Runbook: Health 503 / degraded

1. Подождите ~30 с после старта.
2. Смотрите `checks`:
   - `telegram:false` → токен, сеть, конфликт getUpdates, lease/primary;
   - `discord:false` → токен, intents, gateway;
   - `lease:false` → `/host_status`, consent, TTL.
3. Пустой `HEALTH_PORT` / нет aiohttp → health выключен (не путать с 503).
4. Не открывайте `:8080` в интернет без нужды.

## Runbook: host-sync bad signature

1. На каждом ПК агента — **один** `HOST_SYNC_SECRET` (не публикуйте в чат).
2. Рестарт всех `run-agent.ps1` после смены.
3. Syncthing реально синкает `HOST_SYNC_DIR`.
4. `HOST_SYNC_SECRET is required` = секрет пуст; `bad signature` = секрет **разный** или битый payload.
5. После утечки — rotate на всех ПК ([[Безопасность]]), тест `/host_status`.

## Слэш-команды Discord нет в списке `/`

1. В логе старта есть `Слэш-команды (global)` и `Guild … slash` — иначе процесс упал до sync.
2. Приглашение бота со scope `applications.commands`.
3. В пикере выбран **этот** бот, не второе приложение на сервере.
4. Полностью закройте Discord (не только свернуть) и откройте снова.
5. Процесс `python -m bot.main` должен оставаться запущенным: без него команды в списке не отвечают.

Подробнее: [[Слэш-команды-Discord]].

## FSM после рестарта

Ожидаемо (MemoryStorage). Очередь в SQLite цела. Модератору: снова с карточки / `/cancel`. Автору: `/start` и заявка заново.
