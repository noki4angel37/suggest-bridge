# Слэш-команды Discord

Дата: 2026-08-26

## Что сделано

Список `/` на сервере обновляется сразу после старта бота: команды копируются на гильдию (`copy_global_to` + `sync(guild)`), а не остаются только глобальными (у глобальных задержка до часа). Старт больше не стирает серверные копии.

Имена в API — латиница (`suggest`, `setup_suggest`, `prohodka`, `setup_pass`, …). Русский клиент Discord может показывать локализованные названия, если команда задана через `locale_str(..., ru=...)` и у дерева команд установлен переводчик.

Пока процесс `python -m bot.main` не запущен, команды могут быть в списке, но не выполняются.

## Как устроено

1. После регистрации команд — глобальный `tree.sync()`.
2. При готовности гильдии — копия глобальных команд на этот сервер и `sync(guild=…)`.
3. Повторная публикация на ту же гильдию в одном процессе пропускается (блокировка от гонки `on_ready` / `on_guild_available`).
4. Если Telegram на время недоступен по сети, long polling повторяется; Discord-адаптер при этом не гасится.

На Windows логи пишутся в UTF-8, чтобы эмодзи в именах каналов не роняли процесс через ошибку кодека.

## Как проверить

1. Запустить бот с `DISCORD_TOKEN`.
2. В логе: глобальный sync, затем строка вида `Guild … slash: N […]`.
3. В Discord набрать `/` у **этого** бота (не у другого приложения на сервере).
4. Если список пустой — полностью закрыть клиент Discord и открыть снова (кэш клиента).
5. Процесс не должен сразу завершаться после `Discord-адаптер готов`.

```text
pytest tests/test_bridge_integration.py -q
```

## Ограничения

- Глобальная и серверная копии одной команды иногда видны в пикере дважды — это один обработчик.
- Неверный токен Telegram по-прежнему останавливает процесс (повтор только для сетевых ошибок).
- Неверные scopes приглашения (`applications.commands`) команды не появятся, какой бы sync ни был.
