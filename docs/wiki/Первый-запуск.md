# Первый запуск

Чеклист на **~30 минут** после установки: от заполнения `.env` до первой опубликованной заявки (модуль предложки). Установка и деплой — [[Быстрый-старт]]; переменные — [[Конфигурация]].

> Не коммитьте `.env`. В примерах — только `REPLACE_ME`, не реальные токены.

## 0. Подготовка (≈10 мин)

- [ ] Клонировать репозиторий или распаковать релиз — см. [[Быстрый-старт]].
- [ ] Скопировать шаблон: `cp .env.example .env` (Windows: `Copy-Item .env.example .env`).
- [ ] Запустить автоподготовку: `bash scripts/deploy/prepare-env.sh` или `.\scripts\deploy\prepare-env.ps1`.
- [ ] Заполнить **все** обязательные переменные для выбранного режима (см. [[Выбор-режима]]). Литерал `REPLACE_ME` ≡ «не задано» — бот не стартует или уйдёт в `degraded`.
- [ ] **Telegram:** создать бота (@BotFather), канал, добавить бота админом канала — [[Telegram]].
- [ ] **Discord:** Developer Portal, intents, invite с правами **268561488** — [[Discord]].
- [ ] Убедиться, что `HEALTH_PORT=8080` задан (рекомендуется для Docker / VPS / systemd).

## 1. Запуск процесса (≈5 мин)

Выберите один способ из [[Быстрый-старт]]:

| Способ | Команда |
|--------|---------|
| Docker | `docker compose up -d --build` |
| Python (Windows / dev) | `python -m bot.main` (после venv + `pip install -r requirements.txt`) |
| systemd | `systemctl enable --now suggest-bridge` (env в `/etc/suggest-bridge/env`) |

- [ ] Процесс не уходит в restart loop — смотрите логи (`docker compose logs -f` / `journalctl -u suggest-bridge -n 100`).
- [ ] В логах нет `RuntimeError` про незаполненные токены.

## 2. Health-check (≈2 мин)

```bash
curl -s http://127.0.0.1:8080/healthz
```

- [ ] Ответ JSON: `"status":"ok"` (или `"degraded"` первые ~30 с — дождитесь подключения платформ).
- [ ] В `checks` для активных платформ: `telegram:true` и/или `discord:true`.
- [ ] При `503` / `degraded` — разберите `checks.*` по runbook [[Устранение-неисправностей]].

## 3. Discord: setup сервера (≈5 мин)

Только если в `.env` задан `DISCORD_TOKEN`. Подробности — [[Discord]], схема каналов — [[Схема-каналов-Discord]].

- [ ] Дождаться появления slash-команд после boot (global sync; при кэше клиента — полностью выйти из Discord и открыть снова).
- [ ] Выполнить **`/setup_suggest`** на целевом guild (нужны права setup: админ бота или Manage Guild).
- [ ] Проверить **`/setup_info`** — каналы заявок, модерации и публикации привязаны.
- [ ] *(Опционально)* **`/decorate_server`** — emoji┃имена, категории, ACL ленты.

## 4. Telegram: smoke-test (≈3 мин)

Только если задан `BOT_TOKEN`. Подробности — [[Telegram]].

- [ ] От админского аккаунта (id из `ADMIN_IDS`) написать боту **`/start`** в личку.
- [ ] Бот отвечает интро предложки, меню команд обновилось.
- [ ] *(Опционально)* **`/adminhelp`** в **личке Telegram** — справка админа (в Discord этой команды нет).

## 5. Тестовая заявка и модерация (≈5 мин)

- [ ] **Отправить тестовую заявку:**
  - Telegram: текст в личку → черновик → «отправить на модерацию»;
  - Discord: `/suggest` или сообщение в `#посты-предложения` → подтверждение в ЛС.
- [ ] **Модератор** видит карточку (TG личка и/или Discord) — [[Модерация]].
- [ ] Нажать **«Одобрить»**, при необходимости выбрать цель публикации (TG / DS / both).
- [ ] **Проверить публикацию:**
  - Telegram: пост в канале `CHANNEL_ID`;
  - Discord: пост в `#предложка` (или alias из `SETUP_PUBLISH_CHANNEL_ALIASES`).
- [ ] Автор получил уведомление об одобрении (если настроено поведением карточки).

Если approve прошёл, а поста нет — снова «Одобрить» (retry) и [[Устранение-неисправностей]].

## 6. Зеркало ленты *(опционально, режим both)*

Только если работают **и** Telegram, **и** Discord.

- [ ] В личку боту админу: **`/mirror`** — статус (по умолчанию включено).
- [ ] Опубликовать **обычный** пост в TG-канале (не через модерацию) → копия появилась в Discord `#предложка`.
- [ ] Или наоборот: пост бота/редактора в `#предложка` → копия в TG-канале.
- [ ] При сбое: `/mirror on`, один primary-процесс — [[Модерация#Зеркало-ленты]], [[Устранение-неисправностей]].

## Готово

| Что проверено | Следующий шаг |
|---------------|---------------|
| Health + платформы | [[Эксплуатация]] — бэкапы, логи |
| Модерация end-to-end | [[Команды]] — админ-команды, антифлуд |
| Multi-PC | [[Multi-PC]] — агент и `HOST_SYNC_SECRET` |

Проблемы на любом шаге — [[Устранение-неисправностей]]. Выбор режима до деплоя — [[Выбор-режима]].
