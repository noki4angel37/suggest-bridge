# Миграция на Suggest Bridge

Практический гид для администратора, который переходит с **ручной предложки** (отдельный канал, модераторы копируют посты) или с **другого бота**. Честно: встроенного импорта истории **нет**.

См. также: [[Быстрый-старт]], [[Деплой]], [[Discord]], [[Telegram]].

## Что можно и нельзя перенести

| Данные | Перенос |
|--------|---------|
| Старые заявки / очередь | **Нет** — только вручную из архива канала |
| Настройки другого бота | **Нет** — заново через `.env` и `/setup_suggest` |
| Опубликованные посты в канале | Остаются в TG/DS; бот их не «подхватывает» retroactively |
| Новые заявки после cutover | Да — через Suggest Bridge |

Suggest Bridge хранит состояние в SQLite (`bridge.db`): тексты, статусы, админы, mirror links, settings. Это **новая** база при первом запуске.

## Рекомендуемый порядок

### 1. Подготовка

1. Сохраните **ручной бэкап** старого канала заявок и модерации (экспорт Telegram, Discord audit или просто скриншоты/копии важных pending).
2. Решите **cutover date** — с какого момента заявки принимает только новый бот.
3. Подготовьте `.env` по [[Конфигурация]]; Discord invite **268561488** — [[Discord]].

### 2. Установка параллельно (осторожно)

Можно **кратко** поднять Suggest Bridge рядом со старым процессом для теста **на тестовом** канале/guild. **Не** запускайте два бота с **одним и тем же** `BOT_TOKEN` и long polling — будет `Conflict` / дубли.

Для прода: один primary-процесс на токен.

### 3. Настройка сервера

1. Пригласите бота по OAuth-ссылке (scopes + permissions из [[Discord]]).
2. `/setup_suggest` — каналы заявок, модерации, публикации, роли.
3. При необходимости `/decorate_server` — категории и ACL.
4. Проверьте тестовую заявку end-to-end: submit → карточка → approve → пост в канале.

### 4. Cutover для подписчиков

1. Объявите в старом канале: заявки теперь через бота ([[Как-отправить-заявку]]).
2. Ограничьте или архивируйте старый канал заявок, чтобы не было двух путей.
3. Старые **pending** из ручного процесса доработайте вручную или отклоните с пояснением «отправьте заново боту».

### 5. Старый бот

- Снимите старого бота с сервера или отзовите его token, чтобы подписчики не путались.
- Если старый бот тоже использовал тот же TG-канал — убедитесь, что **один** процесс публикует в канал.

## Зеркало после миграции

Зеркало ленты **не** импортирует старые посты. Оно синхронизирует только **новые** посты в каналах после включения. См. [[Зеркало-ленты]].

## Multi-PC

Если админы работают с нескольких Windows-ПК — настройте агента **после** стабильного single-host запуска: [[Multi-PC]]. Не синхронизируйте через Syncthing `.env` или `bridge.db` — только `HOST_SYNC_DIR`.

## Откат

1. Остановите Suggest Bridge.
2. Верните старый процесс / ручной workflow.
3. Бэкап `bridge.db` сохраните на случай повторной попытки.

## Чеклист после миграции

- [ ] Тестовая заявка TG и/или Discord прошла модерацию
- [ ] `/queue` пуст или понятен
- [ ] Подписчики знают новый путь ([[Как-отправить-заявку]])
- [ ] Старый бот отключён
- [ ] Бэкап `bridge.db` по [[Эксплуатация]]
