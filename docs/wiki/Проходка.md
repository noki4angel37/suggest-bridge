# Проходка

Дата: 2026-08-27

Временная (или бессрочная) роль Discord: участник запрашивает доступ, модератор предложки принимает или отклоняет заявку. Админ сам решает, какие каналы привязать к роли и в каком режиме.

Это **не** тема сервера и не набор мини-игр. Имена каналов выбирает админ.

## Что сделано

- `/prohodka` (в русском клиенте — **`/проходка`**) — заявка на роль.
- `/setup_pass` (RU: **`/настроить_проходку`**) — создать роль (если её нет), создать или пометить канал: режим **скрыть** (канал не виден без роли) или **видно** (канал виден всем; без роли сообщения удаляются). Текст или голос.
- `/pass_config` (RU: **`/срок_проходки`**) — срок выдачи на этом сервере: пресеты или **безлимит** (меняется только для новых выдач).
- Карточка заявки — в канал модерации предложки. Кнопки «Принять» / «Отклонить».
- После истечения срока роль снимается (если срок не безлимитный). Отклонённую заявку нельзя сразу повторить. Есть антиспам.

## Как устроено

1. Админ бота, владелец сервера или носитель админ-роли (`/admin_roles`) вызывает `/setup_pass` (RU: `/настроить_проходку`).
2. Бот находит или создаёт роль проходки (`hoist` выключен, не mentionable), сохраняет id для гильдии, применяет ACL и пишет канал в реестр.
3. Режим **скрыть**: `@everyone` не видит канал; роль проходки и бот видят и пишут.
4. Режим **видно** (текст): канал виден всем; без роли сообщение удаляется сразу, краткое предупреждение ~5 с, затем тоже удаляется. Чужие боты и webhook тоже удаляются; свой бот, носители роли, владелец сервера и админы бота — нет.
5. Голос: канал виден, без роли **Connect** запрещён.
6. Участник: `/prohodka` (RU: `/проходка`) → модератор принимает → роль на срок из `/pass_config` (RU: `/срок_проходки`; иначе `DISCORD_PASS_DURATION_SEC`, по умолчанию 5 часов) или без срока.
7. Бот снимает роль в момент `expires_at` (спит до этой метки, не только «раз в 30 с»). Если процесс был выключен, снимет сразу после запуска. Безлимит не снимает. Если роль снять не удалось (нет гильдии, нет права Manage Roles), запись **не** помечается истекшей — повтор через несколько секунд.

Id роли можно задать заранее через `DISCORD_PASS_ROLE_ID`. После `/setup_pass` сохранённая для сервера роль **важнее** env.

Карточки не уходят в Telegram.

## Как проверить

1. Бот запущен с `DISCORD_TOKEN`, на сервере есть `/setup_suggest` (канал модерации для карточек).
2. `/setup_pass` без параметров — категория «закрытые каналы» (если не было) и канал «проходка» в режиме скрыть.
3. `/setup_pass имя:чат режим:видно` — второй канал, видимый всем; сообщение без роли удаляется.
4. `/setup_pass имя:войс тип:голос` — голосовой канал без Connect для `@everyone`.
5. `/pass_config` — выбрать срок или безлимит.
6. `/prohodka` → карточка в модерации → «Принять».
7. Роль бота в списке ролей сервера **выше** роли проходки.
8. Дождаться конца срока (или перезапустить бота после просрочки) → роль снята, карточка «истекла», в ЛС «срок истёк».

```text
pytest tests/test_pass_service.py tests/test_pass_rooms.py tests/test_pass_guard.py -q
```

## Команды

| API-имя | В RU-клиенте | Кто | Описание |
|---------|--------------|-----|----------|
| `/prohodka` | `/проходка` | участник сервера | Запросить роль |
| `/setup_pass` | `/настроить_проходку` | админ бота / админ-роль / владелец сервера | Роль + канал (скрыть/видно, текст/голос) |
| `/pass_config` | `/срок_проходки` | те же | Срок выдачи на сервере (в т.ч. безлимит) |

Параметры `/setup_pass` (имена параметров в RU-клиенте):

| Параметр | Назначение |
|----------|------------|
| `канал` | Существующий текстовый или голосовой канал |
| `имя` | Имя **нового** канала, если `канал` не указан |
| `категория` | Куда положить новый канал |
| `роль` | Готовая роль проходки; иначе бот найдёт или создаст |
| `режим` | `скрыть` (по умолчанию) или `видно` |
| `тип` | `текст` или `голос` (для нового канала) |

## Переменные `.env` (все опциональны)

| Переменная | Default | Назначение |
|------------|---------|------------|
| `DISCORD_PASS_ROLE_ID` | — | Готовая роль, если `/setup_pass` ещё не вызывали |
| `DISCORD_PASS_COMMAND` | `проходка` | Русское имя в пикере `/` |
| `DISCORD_PASS_LABEL` | `проходка` | Текст на карточке и в сообщениях |
| `DISCORD_PASS_ROLE_NAME` | как `LABEL` | Имя создаваемой роли |
| `DISCORD_PASS_CHANNEL_NAME` | `проходка` | Имя канала, если `/setup_pass` без параметров |
| `DISCORD_PASS_CATEGORY_NAME` | `закрытые каналы` | Категория для новых комнат |
| `DISCORD_PASS_DURATION_SEC` | `18000` (5 ч) | Default срока, если `/pass_config` не вызывали; `0` = безлимит |
| `DISCORD_PASS_REJECT_COOLDOWN_SEC` | `300` | Пауза после отклонения |
| `DISCORD_PASS_ANTISPAM_LIMIT` | `5` | Попыток в окне до временного бана команды |
| `DISCORD_PASS_ANTISPAM_WINDOW_SEC` | `600` | Окно антиспама |
| `DISCORD_PASS_ANTISPAM_STRIKE_SEC` | `900` | Длительность страйка |
| `DISCORD_PASS_DEBOUNCE_SEC` | `8` | Минимальный интервал между вызовами |
| `DISCORD_PASS_EXPIRY_POLL_SEC` | `30` | Пауза, когда нет срочных выдач; при активном сроке бот будит себя к `expires_at` |

## Ограничения

- Без канала модерации предложки карточка не отправится — сначала `/setup_suggest`.
- Существующую публичную категорию `/setup_pass` **не** переписывает целиком: ACL ставится на канал.
- Пока роль выдана (в т.ч. безлимит), повторный `/prohodka` недоступен.
- Чёрный список бота (`/block_user`) блокирует и проходку.
- Роль нельзя полностью спрятать с профиля Discord; бот лишь не выносит её в отдельный список (`hoist` off).
- Без права Manage Messages страж режима «видно» не сможет удалять сообщения.
- Смена `/pass_config` не переписывает уже выданные гранты.
- Для голосовых каналов параметр `режим` не меняет ACL: войс всегда виден, без роли Connect запрещён.
- Страж режима «видно» чистит и сообщения в ветках (threads) родительского канала.
