## Чеклист перед продом

1. `cp .env.example .env` или `scripts/deploy/prepare-env.*` — **заполните** токены до старта
2. Режим и переменные — [[Конфигурация]]
3. `HOST_SYNC_SECRET` — если multi-PC / агент
4. `HEALTH_PORT=8080` — только если нужен probe; ограничьте доступ снаружи
5. Discord intents + invite **268561488** — [[Discord]]
6. Бэкап-план для `bridge.db` — [[Эксплуатация]]

## Docker

```bash
mkdir -p data && sudo chown -R 1000:1000 data   # Linux: user suggest в образе
docker compose up -d --build
docker compose logs -f suggest-bridge
curl -s http://127.0.0.1:8080/healthz
```

- Образ: non-root user `suggest` — без прав на volume запись `bridge.db` падает.
- Volume: `./data` → `/data`, `BRIDGE_DB_PATH=/data/bridge.db`.
- Публикация порта: в compose по умолчанию `8080:8080` (все интерфейсы хоста). Для VPS безопаснее переопределить на `127.0.0.1:8080:8080` или не публиковать и проверять health изнутри — [[Безопасность]].

## systemd

Файл: [contrib/systemd/suggest-bridge.service](https://github.com/noki4angel37/suggest-bridge/blob/main/contrib/systemd/suggest-bridge.service)

- `WorkingDirectory=/opt/suggest-bridge`
- `EnvironmentFile=/etc/suggest-bridge/env` — **единственный** конфиг для unit
- `Environment=HEALTH_PORT=8080`
- `ExecStart=…/python -m bot.main`
- Без `User=` — процесс часто от root; при желании заведите dedicated user и поправьте пути/права
- `Restart=on-failure`, `NoNewPrivileges=true`

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now suggest-bridge
sudo systemctl status suggest-bridge
```

## Health endpoint

| | |
|---|---|
| Bind | `0.0.0.0:HEALTH_PORT` |
| URL | `GET /healthz` |
| 200 | `"status":"ok"` |
| 503 | `"status":"degraded"` |
| Выкл | `HEALTH_PORT` пустой / нечисловой; нет aiohttp |

Пример:

```json
{"status":"ok","checks":{"telegram":true,"discord":true,"lease":true}}
```

| Check | false означает |
|-------|----------------|
| `telegram` | TG не готов / нет токена в этом режиме / polling не поднят |
| `discord` | Discord gateway не готов / нет токена |
| `lease` | callback lease не ok (зависит от wiring при старте) |

Разбор 503: [[Устранение-неисправностей]].

## Обновление без потери данных

```bash
git pull
docker compose up -d --build
# или: pip install -r requirements.txt && systemctl restart suggest-bridge
```

Не удаляйте volume / `data/`. После обновления: health + тестовая заявка. FSM в памяти сбросится — ожидаемо.
