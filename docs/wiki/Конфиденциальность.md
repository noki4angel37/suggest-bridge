# Конфиденциальность

Suggest Bridge — **открытое ядро** Telegram ↔ Discord (self-hosted): данные хранятся на сервере или ПК **администратора сообщества**, а не у разработчика репозитория. Политика безопасности и уязвимостей: [[Безопасность]], [SECURITY.md](https://github.com/noki4angel37/suggest-bridge/blob/main/SECURITY.md).

## Что хранится в `bridge.db`

SQLite-база (`BRIDGE_DB_PATH`, по умолчанию `./data/bridge.db`) — основное долговременное хранилище:

| Таблица / данные | Содержимое |
|------------------|------------|
| **submissions** | Тексты заявок, статус, автор (platform id, отображаемое имя, username), флаг анонимности, даты, причина отклонения, цели публикации |
| **submission_media** | Ссылки на медиа (file_ref, тип контента) |
| **moderation_refs** | Id сообщений модерации в Telegram / Discord |
| **admins** | Список админов бота по платформам |
| **mirror_links** | Связи опубликованных постов между Telegram и Discord |
| **guild_configs**, **settings** | Настройки сервера и бота |
| **blacklist**, **antiflood_hits** | Блокировки и счётчики антифлуда |

Заявки, уже отправленные на модерацию, **сохраняются** при перезапуске процесса.

## Что не сохраняется в базе

- **FSM Telegram** (`MemoryStorage`) — черновики в личке, шаг «ответ автору» и ввод причины отклонения живут **только в памяти** процесса. После рестарта бота незавершённый диалог нужно начать заново (TTL шага ответа — 15 минут).
- **Токены** (`BOT_TOKEN`, `DISCORD_TOKEN`, …) — только в `.env` / переменных окружения на хосте администратора, **не** в `bridge.db`.

## Кэш медиа

Вложения с Discord CDN (и аналогичные) при необходимости скачиваются в каталог **`media/`** рядом с `bridge.db` (`data/media/{submission_id}/`), чтобы отложенная публикация работала после удаления исходного сообщения. Файлы привязаны к заявкам в базе.

## Логи

В логах оператор должен **не публиковать** токены и личные данные. В коде для загрузки URL используется **редакция** (redaction) чувствительных частей URL в сообщениях лога. При обращении в Issues или поддержку — те же правила: без `.env`, без полных логов с секретами.

## Продажа и передача данных

Suggest Bridge **не продаёт** и **не передаёт** данные подписчиков разработчику проекта. Нет центрального облака «от автора бота» — каждый экземпляр принадлежит администратору сообщества.

## Кто контролирует данные

| Роль | Контроль |
|------|----------|
| **Администратор бота** | Владелец хоста, `bridge.db`, кэша `media/`, бэкапов и `.env` |
| **Модераторы** | Видят заявки и могут публиковать / отклонять в рамках прав сообщества |
| **Подписчик** | Отправляет текст и медиа добровольно; может выбрать анонимность при публикации |

Рекомендации по секретам, health-порту и Multi-PC: [[Безопасность]].
